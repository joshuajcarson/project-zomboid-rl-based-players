1. `git log --oneline -8` and read the top of this file.
2. Is a server running? `python -c "import socket;socket.create_connection(('127.0.0.1',17600),timeout=2)"` succeeds if so. Server boot takes about 5 minutes.
3. Never stop java by memory size (server and client are both big). Match command lines: the server has `rl-agent.jar`, rendered clients have `rl-agent-client`.

## Validation gates (avoid investing in dead ends; added 2026-10-26 on the user's request)
A skill only counts as "learned" when all of these hold; otherwise spend the effort on fidelity, not on more training:
1. Fake-backend evaluation beats the scripted baseline or a clear threshold (greedy policy, 4+ episodes, matched spawns).
2. Transfer: the same checkpoint run with one REAL rendered client (backend="mixed", scripts/eval_transfer.py, 10+ episodes) reaches at least ~70% of the fake-only score on the same metric (final pair distance, damage taken). The real client must have the normal load (11 items, one bat, check `inv|user`) and the fake mover must be calibrated to the real runner's speed (scripts/measure_speed.py).
3. If gate 2 fails on two skills in a row, stop training and close the gap (speed, damage model, zombie behaviour, combat) before anything else.
Known fidelity gaps (2026-10-26): combat (real swings land weakly and staggered, fake kills for free: do not train fighting on the fake backend until fixed), zombie damage (synthetic bite rule vs real), zombie aggro/behaviour not compared, only one real client fits in RAM at a time (15.8 GB): a recording with 4 real clients needs a smaller client footprint or another machine.

### 2026-10-30 12:10 drift hunt: time of day is the prime suspect (confound across blocks)
Facts: (1) frame rate was a flat 30 fps (min ~28) in every client session today: machine load is NOT the drift. (2) ANOVA of per-episode damage across the 8 same-policy 1x blocks (n=129): F=2.60 > ~2.1, so the blocks really differ; per-episode sd 27 (heavy right tail: deaths of 80-97 dmg). (3) The server clock runs forward with the server (snapshot at 11:07 = 1:38 AM, daylight 0), so the earlier blocks were fought at different game times: morning ref block (00:30-02:30 wall) ~15-17h daylight: 25.7 dmg, 2/27 deaths; 07:54-08:21 ~21-22h night: 40.4 / 39.6; 09:xx-10:35 ~23-01h: 56.8 / 43.7 / 49.7 with 12 deaths of 35. Night blocks (n=52 incl. earlier two): 12 deaths of 52 vs day/noon blocks 2 of 77 (Fisher p < 0.001). (4) First interleaved arm design was flawed: arm A's changes persisted into arm B (client clock reset by the server, corpses stayed cleared), so both arms were effectively noon with ~0-24 corpses (noon blocks: 40.3 n=20 and 30.2 n=30, 0 deaths in 50). Corpses alone (232 vs 0) are therefore NOT a strong effect at noon; darkness is the candidate. Fix: set the SERVER clock per arm (server settime is authoritative), then rerun noon vs 1 AM interleaved, corpses cleared in both. ALSO: every previous comparison (swing distance, retreat, 2x clock, +delay) was confounded by game time of day: re-evaluate them at a fixed time of day.

### 2026-10-30 13:35 drift hunt RESULT: darkness is not it; corpses might add ~10 damage; the rest is noise
Interleaved arms inside ONE session (even/odd episodes), fight-v4, charge:1.8:0, 1x, seed 7 (tools: env PZ_ARM_ALTERNATE/PZ_ARM_HOUR/PZ_ARM_B_HOUR/PZ_ARM_PILE, client bot commands `world`, `arm`, `pile`; analysis scripts/compare_arms.py):
- Noon vs 1 AM (server clock set per arm, corpses cleared in both; 40 eps, 20/arm): noon 1.30 kills / 31.4 dmg; 1 AM 1.35 / 32.7; 0 deaths in 40. Darkness has NO effect.
- Cleared vs pile of 250 fresh bodies (noon both; 36 real eps): cleared 1.82 kills / 24.5 dmg (n=17, 1 death); pile (239 bodies) 1.58 / 34.9 (n=19, 3 deaths): damage +10.4 (se 8.3, z 1.25), kills -0.24 (se 0.22, z -1.1): same direction as the hypothesis, NOT significant. Needs ~3x more episodes to settle.
- So the large block-to-block differences (25.7 to 56.8 damage) are mostly NOT explained by time of day; with sd ~27 and n of 7-16 per block, plain sampling noise explains a lot of it (the ANOVA across blocks was only F=2.6), plus possibly corpses (the death-heavy blocks all had ~230 bodies). Cleared-field blocks today: 40.3 (n=20), 31.4, 32.7, 24.5: SE ~5-8 each, so they agree within noise.
- RULES from now on: (1) compare variants only INSIDE one interleaved session (lab accepts comma-separated policies that alternate by episode: `charge:1.8:0,charge:2.2:0`, tag `policy` in each episode line; scripts/compare_arms.py --by policy); (2) 30+ episodes per arm and report z; (3) keep the field clean: corpses are 2 per fight and piled to ~230 over a day. (4) Everything earlier (swing distance 1.8-2.6 equal, retreat no help, 2x clock, +300 ms) was compared across blocks: treat as unconfirmed except the large effects (1.3 and 3.0 swing distance clearly worse: damage 55 and 42 vs 25-31).
- Backlog: corpse invariant at reset (clear when > ~50 bodies within 35 tiles; needs a client `clear` command without the clock change); rerun the key comparisons interleaved: swing distance 1.8 vs 2.2, retreat 35 vs 0, 1x vs 2x clock (same server session needs both scales: not possible; use two sessions with interleaved halves or accept a cross-session design with 60 eps per arm).
